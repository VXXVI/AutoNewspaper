# 中国教育报整家漏报：诊断与修复记录（2026-09-29）

> 面向维护者：记录一次「代码明明修好了，包里却没有」的完整定位过程。
> 使用者只需看 [CHANGELOG 的 1.0.4](../CHANGELOG.md)（修复随 1.0.4 发布，1.0.3 无产物）。

## 一句话结论

发布包（Windows x64 / Win7）里**没有** TLS 修复代码，因此中国教育报在 Win7 上
**整家 0 版面 0 文章**；主机之所以"看着正常"，只是因为系统自带 `curl.exe` 在兜底。
真正的原因是那次修复**没有推送到远程仓库**，而包是 CI 从远程代码构建的。

## 现象

Win7 虚拟机里跑看板扫描，六家报社里只有中国教育报整家消失：

```
✗ 中国教育报 09-29  版面  0  文章   0  命中 0  网络层失败：curl 无响应（…）
⚠️  2 个报社/日期出现入口失败或扫描异常（中国教育报、中国教育报），结果可能漏报！
```

其余 5 家正常。那句「curl 无响应」是**误导性文案**——真实原因是「这台机器上根本没有
curl」，不是网络异常。

## 证据链

### 1. 包层：exe 里没有 TLS 修复模块

PyInstaller 的单文件 exe 内含明文可解析的 `PYZ-00.pyz` 模块目录表。解析 v1.0.0 ~ v1.0.2
全部发布包，`newspaper_auto.*` 都是 **24 个模块、且不含 `tls`**：

```
cli, config, dialogs, exe, exporter, fsutil, http, papers, parse, paths, procutil,
report, scanner, state, web, web_daemon, web_dashboard, web_handlers, web_papers,
web_scan, web_server, web_static, web_tasks, web_validate
```

解析方法（TOC 本身就是 marshal 数据，**没有**再套 zlib；先按 zlib 解压会报
`incorrect header check`）：

```python
import marshal, struct

data = open("NewspaperAuto.exe", "rb").read()
i = data.find(b"PYZ\x00")
offset = struct.unpack(">I", data[i + 8 : i + 12])[0]
mods = [e[0] for e in marshal.loads(data[i + offset :]) if isinstance(e, tuple)]
print("含 TLS 修复:", "newspaper_auto.tls" in mods)
```

> 该检查已固化进 `scripts/check_exe_tls.py`，每次打包后由 `scripts/build_windows.ps1`
> 自动跑一遍（`tests/test_packaging.py` 用合成字节单测解析器本身）。
>
> 附记（1.0.3 首次发布踩的坑）：这段自检原本内联在 `build_windows.ps1` 里写成
> `python -c`，而 CI 的 Windows runner 控制台是 **cp1252**，脚本里一句
> `print("…含 newspaper_auto.tls")` 就抛 `UnicodeEncodeError`、非零退出，
> 于是两个 Windows 构建 job 双双报「**exe 缺少 TLS 修复模块：打出来的是不含本次修复的代码**」——
> 而 exe 其实完全正常。于是抽出成独立文件并把输出限定为纯 ASCII。

### 2. 运行时层：对照实验证明主机靠 curl 兜底

在主机上跑一次「只扫中国教育报」，再把 curl 从子进程 PATH 中抽掉，跑完全相同的命令：

| 条件 | 结果 | 日志特征 |
|---|---|---|
| 有 curl（主机默认） | 教育报抓到了（09-29 版面 10 / 文章 33） | `标准库抓取失败 …SSLV3_ALERT_HANDSHAKE_FAILURE` × 77；「握手被拒」× 0 |
| 无 curl（受限 PATH） | 教育报 **版面 0 文章 0**，退出码 1 | `标准库抓取失败` × 6；「握手被拒」× 0；「放宽」× 0 |

「握手被拒，改用放宽套件重试」这句日志出现 0 次 → exe 里的 `http.py` 根本没有重试
逻辑，与包层结论互相印证。**主机之所以"看起来没问题"，完全是因为系统自带 curl。**

## 根因：两台机器卡在完全不同的环节（最容易误判的地方）

| 环境 | Python / OpenSSL | 站点给出的报错 | 卡在哪一步 | 补根证书有用吗 |
|---|---|---|---|---|
| 主机（win-x64） | 3.13 / OpenSSL 3.x | `SSLV3_ALERT_HANDSHAKE_FAILURE` | **密码套件**：站点只提供 `AES128-SHA`（RSA 密钥交换 + SHA1），默认 `SECLEVEL=2` 直接禁用 → 连证书都没换到 | ❌ 没用 |
| 虚拟机（win7） | 3.8 / OpenSSL 1.1.1 | `CERTIFICATE_VERIFY_FAILED: self signed certificate in certificate chain` | **证书链**：Win7 系统根库缺锚点 `USERTrust RSA Certification Authority` | ✅ 有用 |

该站证书链（实测取回）：

```
*.jyb.cn → WoTrus RSA OV SSL CA 2 → Sectigo Public Server Authentication Root R46
        → USERTrust RSA Certification Authority（自签根，2010-02-01 ~ 2038-01-18）
```

站点把**整条链（含自签根）**都发了出来，客户端信任库必须有 `USERTrust RSA CA`
（或直接信 `Sectigo R46`）才算得通。

**这条区别决定了修复手段**：只补根证书，Win7 好了而主机照旧（还靠 curl 撑着）；
只放宽套件，Win7 好了而主机也不再依赖 curl。**两件都要做。**

## 修复

新增 `src/newspaper_auto/tls.py`（详见该文件模块文档）：

1. `strict_context()` —— 系统根库之上**追加**随包 `cacert.pem`（Mozilla 根证书包，
   121 张根 CA），补「系统根库缺的锚点」，不替换系统信任；
2. `relaxed_context()` —— 只把安全级别降到 1（`DEFAULT@SECLEVEL=1`），证书校验始终
   开着，降的只是套件强度；
3. 降级**按需**触发：只在失败发生在握手层、**且不是**证书问题时重试一次；放宽后成功
   一次就记住「本机需要放宽」，后续请求直接走放宽上下文。

顺带把 `code == 0` 的失败文案分成两种：机器上没装 curl 时不再说「curl 无响应」。

## 验证

**判据一句话：没有 curl 也能抓到教育报，才算修好了。**

在 macOS / OpenSSL 3.5.5 上复现同一故障（默认上下文握手被拒）并验证修复 —— 抽掉
PATH 里的 curl 后：

```
✓ 光明日报  09-29  版面 17  文章  74  命中15
✓ 南方日报  09-29  版面 46  文章 128  命中11
✓ 羊城晚报  09-29  版面  8  文章  37  命中 2
✓ 中国教育报 09-29  版面 10  文章  33  命中 9
✓ 湛江日报  09-29  版面  9  文章  45  命中 6
✓ 人民日报  09-29  版面 20  文章  88  命中16
```

退出码 0，无「结果可能漏报」。修复前同一条件是中国教育报 0 版面 0 文章。

日志里应能看到此前一次都没有的两行：

```
握手被拒，改用放宽套件重试 https://paper.jyb.cn/...

各站的套件需求实测（其余五家不受影响，放宽前后结果完全一致）：

```

中国教育报                                            strict SSLV3_ALERT_HANDSHAKE_FAILURE，relaxed HTTP 200

## 防复发

「源码修好但没进包」这类事故不会自己暴露，因此在打包链路上钉了四道闸门：

| 闸门 | 位置 | 作用 |
|---|---|---|
| spec `datas` 带 `cacert.pem` | `packaging/NewspaperAuto.spec` | exe 里真的有证书包 |
| `package-data` / `MANIFEST.in` 收录 | `pyproject.toml`、`MANIFEST.in` | wheel 与 sdist 里也有 |
| 打包后读 exe 的 PYZ 目录表 | `scripts/build_windows.ps1` | `newspaper_auto.tls` 确实在包里 |
| wheel 冒烟校验 | `.github/workflows/release.yml` | 分发出去的包里也有 |

四道声明本身由 `tests/test_packaging.py` 在每次 CI 上钉死，删任何一处都会红。

> 另有一条**流程**上的教训：CI 从远程代码构建，所以**修复必须推送上去才算数**。
> 推完用 `git ls-remote origin refs/heads/main` 与本地 HEAD 逐字符复核。
